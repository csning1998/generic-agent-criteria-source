# **§ 202. Test Driven Development**

§ 202 applies when the owner or project documentation declares the repository a TDD repository. § 202 covers production and test mutation in Python, TypeScript, Go, HCL, and YAML trees which the declaration covers.

- **(a) Function Shell and Failing Test Prerequisite**：Prior to any write of production code which is intended to satisfy an automated test, the system MUST establish the minimal function shells, type signatures, and stub exports necessary for test compilation and module resolution. The system MUST write an automated test. The system MUST execute the automated test. The automated test MUST fail for a logical assertion reason which demonstrates the missing behavior. Presenting a compilation failure, syntax error, or unhandled missing module error as an authorized failing test result is strictly prohibited.
- **(b) Red Result Presentation**：The failing assertion test result MUST be presented to the owner before any production code write which targets the same behavior. The system MUST NOT write production code for that behavior until the owner has reviewed the failing result and has explicitly authorized progress into the green step.
- **(c) Pre Presentation Lint and Typecheck**：Prior to presentation of a failing test result, every project linter and static typecheck which applies to a test file or stub file modified in the same step MUST pass. A lint or typecheck failure MUST be resolved in the same step. Presentation of the failing test result MUST NOT occur while a lint or typecheck failure remains.
- **(d) Post Authorization Verification**：After the owner authorizes progress into the green step, the system MUST re execute the minimal automated test set which covers the change. The system MUST re execute every applicable project linter and typechecker in the same turn. Reporting MUST follow § 111.
- **(e) Hygiene and Authorization**：Hygiene work which the repository already declares（linter repair, formatter repair, and equivalent local verification repair）MUST be completed by the system. Asking the owner whether to perform that hygiene work MUST NOT replace completion of the hygiene work. A mutation outside the authorized duty MUST NOT proceed. The system MAY ask a clarifying question. The system MUST NOT begin a mutation until the owner has given explicit authorization for that mutation.
