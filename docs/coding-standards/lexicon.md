# Lexicon and Function Naming Conventions

This document defines the normative lexicon for the criteria hook system and the structural rules for function names across Python packages and test suites in this repository. Each term in this document corresponds to exactly one engineering definition across this specification and the implementing code.

## Section 1. Leading Verb Operational Contract

Function names MUST use a leading verb without prepositional suffixes (§ 306). The leading verb MUST determine the operational behavior, computational complexity, and side-effect expectations.

This table governs every `def` under `hooks/`, comprising module-level functions, instance methods, classmethods, and private helpers with a single underscore prefix. The entry point `main()` and Python special dunder methods (`__init__`, `__repr__`, and equivalent methods) MUST remain exempt from this table. Test functions MUST follow Section 4. Multi-word compound names MUST place the leading verb before the object (for example `has_prompt_capability`). Every identifier in this document, including domain nouns composed of a verb and an object, MUST lead with the verb (for example `ScanPrompt`).

| Verb Category                   | Permitted Leading Verbs                                     | Operational Contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Prohibited Colloquial Verbs                              |
| ------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| **Predicate (Boolean)**         | `is_`, `has_`                                               | `is_` MUST test an intrinsic, static property or identity of the argument. `has_` MUST test whether the argument contains a named attribute or component. The function MUST return a boolean value (`True` or `False`). The function MUST NOT mutate state.                                                                                                                                                                                                                                                                                                                                                                                   | `check_`, `test_` (in prod), `flag_`, `matches_`, `are_` |
| **In-Memory Transformation**    | `extract_`, `compute_`, `derive_`, `normalize_`             | `extract_` MUST isolate one sub-value within a larger structure without altering the source. `compute_` MUST calculate a new scalar through arithmetic or an algorithm. `derive_` MUST produce a new structured value by combining multiple structured inputs. `normalize_` MUST map field names of one envelope onto a fixed target field set, and MUST NOT apply policy. Functions in this category MUST perform pure in-memory computation, extraction, or filtering. Functions in this category MUST NOT perform disk or network operations.                                                                                              | `get_`, `calc_`, `find_`                                 |
| **Input Output Transformation** | `load_`, `parse_`, `render_`                                | `load_` MUST access disk or external data streams. `parse_` MUST convert bytes or text to structured records. `render_` MUST convert structured data to formatted text.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | `read_`, `make_`, `build_`                               |
| **Search / Resolution**         | `find_`, `resolve_`                                         | `find_` MUST return the matching element or `None`. `resolve_` MUST calculate a path or target using environmental or lookup state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | `match_` (when returning item), `lookup_`                |
| **State Mutation**              | `record_`, `persist_`, `reconcile_`, `provision_`, `clear_` | `record_` MUST append a new state entry deterministically and idempotently for the create case. `persist_` MUST write a structured document to a durable store, and MAY overwrite an existing document. `reconcile_` MUST propagate a state value from a source to a target in one direction only. `provision_` MUST idempotently establish a precondition (for example a directory with fixed permissions), removing any conflicting existing entry prior to creation. `clear_` MUST reset accumulated state back to its initial empty value. Functions in this category MUST perform deterministic state mutation on disk or shared memory. | `mark_`, `save_`, `do_`, `set_`, `ensure_`               |
| **Diagnostics**                 | `inspect_`, `validate_`                                     | `inspect_` MUST read the current state of a target and MUST classify that state into a defined enum or token. `validate_` MUST check the target against a specification, and MUST return structured findings or raise a validation error.                                                                                                                                                                                                                                                                                                                                                                                                     | `check_`, `audit_`                                       |
| **Policy Enforcement**          | `enforce_`, `require_`                                      | `enforce_` MUST terminate execution or MUST inject context when a boundary violation is detected. `require_` MUST check a single precondition, returning without side effects on success and denying execution on failure.                                                                                                                                                                                                                                                                                                                                                                                                                    | `gate_`, `ensure_` (when gating)                         |
| **Event Hook**                  | `intercept_`, `dispatch_`                                   | `intercept_` MUST serve as the top-level entry point for one tool-call category, routing the call onward. `dispatch_` MUST route an already classified event to the single handler matching a discriminant value.                                                                                                                                                                                                                                                                                                                                                                                                                             | `handle_`, `process_`, `on_`                             |
| **Exclusive Claim**             | `claim_`                                                    | `claim_` MUST attempt an atomic, exclusive state change using a primitive which admits only one successful caller among concurrent callers (for example `O_CREAT \| O_EXCL`). The function MUST return `True` for the caller whose attempt succeeded, and `False` for every other caller. The state change MUST be durable before this call returns.                                                                                                                                                                                                                                                                                          | `try_`, `attempt_`                                       |
| **Generator (Iteration)**       | `iter_`                                                     | `iter_` MUST yield a lazy sequence of derived values from already loaded data. The function MUST NOT perform disk or network operations. The function MUST NOT be called for a side effect. The caller MUST consume the yielded values.                                                                                                                                                                                                                                                                                                                                                                                                       | `each_`, `walk_`, `loop_`                                |
| **Boundary Output**             | `emit_`                                                     | `emit_` MUST write an encoded decision to the process boundary (`stdout`) and MUST terminate the process. The function MUST NOT contain policy logic. The decision MUST be fully formed prior to this call.                                                                                                                                                                                                                                                                                                                                                                                                                                   | `print_`, `output_`, `write_`                            |

## Section 2. Domain Noun Lexicon

This section defines the domain nouns for the PreToolUse hook system under `hooks/adapters/`. Each noun states its engineering definition and any existing counterpart in the codebase. An absent code counterpart indicates that the noun has not yet been made concrete. Absence of a counterpart does not indicate an existing implementation.

| Term                   | Definition                                                                                                                                                                                                                                                                   | Existing Counterpart                                                          |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `Criteria`             | The specification corpus located at `~/.agents/criteria/`, comprising `1_model_behavior/`, `2_context/`, `3_register/`, and `4_L2-trigger/`.                                                                                                                                 | `CRITERIA_DIR` (`gate-check.py:32`)                                           |
| `Harness`              | The agent product which executes the hook process. Claude Code, Cursor, and Grok TUI each constitute a Harness.                                                                                                                                                              | The object `is_cursor_harness()` detects                                      |
| `Agent`                | The model executing inside a Harness. An Agent MAY execute under different Harness instances. The Harness determines Capability set membership rather than the model name.                                                                                                   | None                                                                          |
| `Envelope`             | The raw JSON object which a Harness writes to the standard input stream of the hook process. Field names vary across Harness implementations.                                                                                                                                | The return value of `json.load(sys.stdin)` in `main()`                        |
| `Request`              | The normalized, harness-agnostic field set produced from an Envelope.                                                                                                                                                                                                        | The return value of `normalize_payload()`                                     |
| `Scenario`             | A frontmattered criteria markdown specification located under `2_context/scenarios/`, constituting one element of the `Criteria` corpus.                                                                                                                                     | Elements of `load_scenarios()`. `CursorScenario` in `cursor_mdc.py:17`        |
| `Verdict`              | The harness-agnostic decision produced by evaluating a Request against a Scenario.                                                                                                                                                                                           | Not yet concrete. Implicit today in the call timing of `deny()` and `allow()` |
| `Response`             | The JSON object encoded for the standard output stream of a specific Harness, representing a Verdict.                                                                                                                                                                        | The `json.dumps` argument inside `deny()` and `allow()`                       |
| `Capability`           | A boolean-valued facility which a Harness provides or omits.                                                                                                                                                                                                                 | Not yet concrete                                                              |
| `AuthorizationChannel` | The communications channel through which owner authorization reaches the hook process, available when `has_prompt_capability`, `is_answer_readable`, and `is_answer_attributable` all evaluate to `True`.                                                                    | Not yet concrete                                                              |
| `AuthorizationSignal`  | Evidence of owner authorization which is readable during PreToolUse evaluation and attributable to the owner.                                                                                                                                                                | The target of the search `extract_latest_user_prompt()` performs              |
| `ExecPhrase`           | A literal string token which constitutes an AuthorizationSignal for a given Harness.                                                                                                                                                                                         | `EXEC_PHRASES` (`gate-check.py:37`)                                           |
| `ScanPrompt`           | The span of transcript text extending from the latest verified user message through subsequent trailing tool results, which provides the search space for an AuthorizationSignal. The identifier uses the leading verb `Scan` per the verb-first ordering rule in Section 1. | The buffer `extract_latest_user_prompt()` accumulates                         |
| `ContextPayload`       | The concatenated text of the files referenced by the `load:` declaration of a Scenario, prepared for inclusion in the Response of a Harness.                                                                                                                                 | The return value of `render_scenario_bundle_text()`                           |
| `EnforceReceipt`       | A filesystem token which verifies that a Scenario has completed its Enforce action during the current session. Presence of this token transitions the Verdict for the Scenario from deny to allow.                                                                           | The file `resolve_marker_path()` addresses                                    |

## Section 3. Domain Verb Lexicon

Each domain action MUST bind directly to one leading-verb prefix defined in Section 1. This table provides the complete operational contract for domain actions. Section 1 remains the authoritative source governing leading-verb prefixes.

| Domain Action | Definition                                                                       | Prefix       | Operational Contract (quoted from Section 1)                                                                      |
| ------------- | -------------------------------------------------------------------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------- |
| Normalize     | Converts an Envelope into a Request.                                             | `normalize_` | Performs pure in-memory field mapping. MUST NOT apply policy.                                                     |
| Find          | Resolves a Request to a matching Scenario.                                       | `find_`      | Returns the matching element or `None`.                                                                           |
| Derive        | Calculates a Verdict from a Request, a Scenario, and the active Capability set.  | `derive_`    | Performs pure in-memory computation. MUST NOT perform disk or network operations. MUST NOT terminate the process. |
| Render        | Converts a Verdict into a Response formatted for a specific Harness JSON schema. | `render_`    | Converts structured data into formatted text.                                                                     |
| Emit          | Writes an encoded Response to standard output and terminates the process.        | `emit_`      | Writes an encoded decision to the process boundary. MUST NOT contain policy logic.                                |
| Resolve       | Identifies the Harness executing the current process.                            | `resolve_`   | Calculates a target using environmental or lookup state.                                                          |
| Extract       | Isolates an AuthorizationSignal from the text of a ScanPrompt.                   | `extract_`   | Performs pure in-memory extraction. MUST NOT perform disk or network operations.                                  |
| Enforce       | Denies a Scenario once and injects the corresponding ContextPayload.             | `enforce_`   | Enforces policy by terminating execution or injecting context upon a boundary violation.                          |
| Record        | Writes an EnforceReceipt to the filesystem.                                      | `record_`    | Performs deterministic state mutation on disk or shared memory.                                                   |

## Section 4. Test Function Naming Specification

Test functions MUST serve as executable specifications following a three-tier naming structure:

```python
def test_<target_unit>_<condition_or_input>_<expected_behavior>(): ...
```

- `<target_unit>`: The identifier MUST specify the exact normalized name of the function or component under test.
- `<condition_or_input>`: The identifier MUST specify the precise setup, input state, or constraint.
- `<expected_behavior>`: The identifier MUST specify the deterministic assertion outcome (for example `returns_...`, `aborts_without_mutation`, `raises_...`, or `flags_violation`).
- Colloquial narrative terms (including `happy_path`, `works`, `can_handle`, and `fail`) MUST NOT appear in test function identifiers.
